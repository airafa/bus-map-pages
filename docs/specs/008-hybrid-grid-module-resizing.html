Specification: Hybrid Grid Module Resizing ​

Status, sources, and precedence ​

  • Status: historical. Superseded by the plug-and-play ResizableSplit component; the current contract is the module resizing package README. The config shape, gridTemplateColumns parsing, and storage-side limits below no longer exist.
  • Derived from the published hybrid guide, including its drag-performance safeguards.
  • Supersedes the pane sizing, limits, and interaction mechanism in Historical Flexbox Module Resizing and the conflicting 25:75/25–75 pane requirements in Consolidated Requirements.
  • Original walkthroughs remain in the table documentation. Their duplicate application-root files have been removed in favor of these specifications.

1. Goal and scope ​

Provide a native, accessible two-pane separator that previews resizing without per-movement React state updates, commits the chosen ratio to a dedicated Redux DataSource, and persists through an exclusively selected local or remote backend.

On viewports below 840 CSS pixels, keep the separator visible and resize stacked rows instead of side-by-side columns.

No new splitter library or Web Component shall be introduced. Existing module hosts and editor drag-and-drop infrastructure remain outside this refactor.

2. Configuration contract ​

FieldContract
layout.uuidStable, nonblank preference identity; reject reserved prototype-property IDs

general.userPreferences.urlnull/omitted for local mode, nonempty string for remote mode

  • HG-01: Derive the default first-pane percentage from the two configured weights: first / (first + second) * 100.
  • HG-02: Validate 0 < minPercent <= defaultPercent <= maxPercent < 100.
  • HG-03: Current dashboard defaults shall be 50fr 12px 50fr with 20–80% limits and userPreferences.url: null.
  • HG-04: An ineligible content count shall not render a separator or initiate preference loading. It shall not pretend to support multi-pane splitting.
  • HG-05: Layout configuration shall retain composition and default geometry; saved user ratios shall not rewrite the generic layout tree.

3. Ownership and architectural boundaries ​

Composition, layout paths, defaultsExisting layout service/configuration

--panel-first, --panel-secondReact-rendered committed styles

  • HG-06: Pointer movement shall neither dispatch preference actions nor call generic updateLayout nor set React component state.
  • HG-07: React shall never render preview variables; preview code shall never mutate committed geometry variables.
  • HG-08: At rest, no preview variables or active-drag marker shall remain.
  • HG-09: Initialize the shared preference store before consumers register panels. Reinitializing an in-use store shall throw.
  • HG-10: Share a single preference DataSource across independent application and editor React roots. The hook shall not depend on their surrounding Redux providers or create a store per panel.
  • HG-11: Keep DOM elements, pointer refs, animation IDs, and requests out of persisted preferences.
  • HG-12: Preserve module placement, lifecycle, and existing editor DnD handlers.

4. Preference state and async operations ​

Each UUID shall have a ratio, load status, save status, and optional current save request ID/error. Statuses shall distinguish pending persistence from successful persistence.

  • HG-13: Use Redux Toolkit slice reducers and async load/save thunks; inject storage operations through thunk middleware.
  • HG-14: Validate IDs, defaults, and selected percentages before pending actions insert/update state. Invalid requests shall log an error and be rejected.
  • HG-15: Load only absent/idle entries, preventing duplicate consumer loads. A failed load shall not automatically retry.
  • HG-16: Save pending shall optimistically commit the chosen ratio before persistence resolves, restoring React-owned geometry without network delay.
  • HG-17: Late loads shall not overwrite a newer user save. Only the current save request ID may settle the current save status.
  • HG-18: Serialize backend operations per UUID; failure shall not block a later operation. Different UUIDs shall not share a single serialization queue.
  • HG-19: The hook shall subscribe to that UUID's immutable snapshot using useSyncExternalStore, return a bounded ratio, and expose save/load statuses.

5. Persistence contract ​

5.1 Local mode ​

  • HG-20: With URL null or omitted, use only localStorage; never fetch preferences.
  • HG-21: Key format shall be busmap:user-preferences:${encodeURIComponent(layoutId)}.
  • HG-22: Store JSON shaped as { "splitPercent": number }.
  • HG-23: On first load with a missing record, write and return configured defaults. Later loads shall restore the stored ratio.
  • HG-24: Validate stored data. Clamp a valid ratio to changed configuration limits; malformed records/storage failures shall log and reject rather than silently overwrite data.
  • HG-25: Document origin-scoped storage; localhost and an IP address are distinct origins. No account isolation or cross-tab synchronization is provided.

5.2 Remote mode ​

  • HG-26: With a nonempty URL, never access localStorage, including on failure.
  • HG-27: GET and PUT shall use the configured resource with a layoutId query parameter, preserving other query parameters.
  • HG-28: Successful nonempty GET data shall contain a valid splitPercent; apply current bounds to a valid stored percentage.
  • HG-29: GET 404, 204, blank body, JSON null, or empty JSON object shall use defaults without automatically writing them to the server.
  • HG-30: PUT shall send { "splitPercent": number } as JSON and accept an empty successful response body.
  • HG-31: Requests shall use a 15-second timeout. Other HTTP, parsing, malformed data, or network errors shall reject; there is no local fallback.
  • HG-32: Server routing, authentication, authorization, per-user isolation, and cross-origin configuration are host responsibilities, not implemented here.

5.3 Failure presentation ​

  • HG-33: Log operational failures with console.error and record failed Redux status/error without user notifications.
  • HG-34: Save failure shall retain the optimistic visible ratio, without rollback or automatic retry. A later completed edit may attempt another save.
  • HG-35: A visible ratio shall not be treated as evidence of durable storage success. Failed initial loads retain a default-backed view and failed status.

6. Pointer interaction ​

6.1 Start ​

  • HG-36: Start only for the primary button, a visible separator, and no existing active drag. Focus the divider, prevent selection, and stop editor propagation.
  • HG-37: At pointer down, measure bounds, padding/borders, current viewport axis, and computed horizontal RTL direction. Cache these for the gesture.
  • HG-38: Available space shall equal the measured axis dimension minus its padding/borders and the fixed 12px divider. Nonpositive space shall throw.
  • HG-39: Store pointer ID, starting coordinate/ratio, available space, axis, direction, and latest ratio in a ref. Capture the pointer, then mark the panel data-is-dragging="true".

6.2 Movement ​

text
coordinate = vertical ? clientY : clientX
directionSign = horizontal RTL ? -1 : 1
requested = startPercent +
            (coordinate - startCoordinate) / availableSpace * 100 * directionSign
next = min(maxPercent, max(minPercent, requested))
  • HG-40: Use relative movement so grabbing a divider edge does not jump the split.
  • HG-41: Ignore other pointer IDs.
  • HG-42: Update the latest desired value in refs and schedule at most one pending animation frame. A callback shall use the latest ratio, not a stale event.
  • HG-43: An unchanged clamped ratio shall not schedule redundant preview work.
  • HG-44: Neither movement nor its frame callback shall call layout/style measurement APIs.
  • HG-45: The preview shall write only preview variables and rounded live aria-valuenow. Grid layout/painting may still occur; this is not compositor-only animation.

6.3 Finish and invalidation ​

  • HG-46: Normal pointer up shall derive the final ratio from its release coordinate even if a pending frame has not run.
  • HG-47: Pointer cancellation or lost capture shall commit the latest recorded ratio. A follow-up lost-capture event shall not double-save.
  • HG-48: Cancel pending animation work, remove previews/drag marker, save once, and release capture if held.
  • HG-49: Unmount, committed preference/bounds changes, enabled-state changes, or breakpoint changes shall cancel obsolete preview work and release capture without saving the abandoned gesture.
  • HG-50: Same-axis geometry is sampled at gesture start; arbitrary container resizing during that gesture is not continuously remeasured.

7. Responsive Grid, RTL, and accessibility ​

  • HG-51: Use the identical (width < 840px) query in CSS and JavaScript. Exactly 840px shall use horizontal pane sizing.
  • HG-52: Desktop shall render pane/divider/pane columns and one row; mobile shall render one column and pane/divider/pane rows.
  • HG-53: Keep the mobile divider visible at full width and 12px height with a row-resize cursor; desktop uses a 12px width and col-resize cursor.
  • HG-54: Use minmax(0, ...), zero Grid gap, and shrinkable pane minimums. Ancestors shall provide a meaningful height for vertical proportional sizing.
  • HG-55: Grid tracks shall prefer preview variables when present, otherwise React-owned committed variables. Remove conflicting inline row/column tracks from enabled panels.
  • HG-56: Use touch-action: none and user-select: none on the divider; retain visible focus styling. On devices with a coarse pointer, extend its hit area to 44px across the movement axis without changing the 12px Grid track. Focus the separator without scrolling the viewport when starting a gesture.
  • HG-57: Render a named, focusable separator with min/max/current ARIA values. Its line orientation shall be vertical for columns and horizontal for rows.
  • HG-58: LTR Left/Right and vertical Up/Down shall decrease/increase the first pane by one percentage point. Invert horizontal arrows in RTL only.
  • HG-59: Home/End shall choose configured minimum/maximum. Ignore wrong-axis keys and keyboard resizing during an active pointer gesture.
  • HG-60: Handled keys shall prevent page scrolling/editor propagation, clamp, and save directly through Redux without imperative geometry preview.
  • HG-61: Use one saved first-pane ratio for both desktop and mobile orientations.

8. Drag performance safeguards and targets ​

  • HG-62: While dragging, disable panel transitions using a scoped rule.
  • HG-63: Disable pointer events on non-divider direct children and their descendants; preserve divider input and restore targeting on every exit.
  • HG-64: Do not add Grid will-change as a claimed GPU acceleration mechanism. Grid sizing remains layout work.
  • HG-65: Do not suppress legitimate content updates or change module behavior merely to claim no React renders. Child timers, resize observers, painting, and unrelated subscriptions remain active.
  • HG-66: Target smooth interaction within a roughly 16.7ms frame budget on a representative 60Hz test device. Report actual frame distribution and long tasks, content, and environment; do not promise a universal 60fps threshold.

9. Integration and editor requirements ​

  • HG-67: Forward UUID, complete layout item, styles, recursive children, and assigned modules through the existing renderer.
  • HG-68: The editor's Panel split (%) field shall read/write the same preference UUID, validate numeric input against limits, and save on blur.
  • HG-69: Keep the divider width consistent across configuration parsing, pointer calculations, and CSS.
  • HG-70: Port through the destination's actual module boundaries, dependency versions, design system, initialization order, and offline artifact workflow. Do not blindly replace application-specific editor integrations.
  • HG-71: Local preference mode shall require no preference server; it shall not imply unrelated application assets or map services operate offline.

11. Non-goals and known ceilings ​

  • More than two resizable content elements.
  • Separate desktop/mobile ratios, pixel minimum guarantees, or continuously remeasured gesture geometry.
  • New Web Components, a new splitter library, or removal of existing hosts.
  • Server implementation, remote user isolation, local fallback in remote mode, automatic retries/rollback, or cross-tab preference synchronization.
  • Undo, snapping, collapse, double-click reset, or guaranteed hardware acceleration.
  • A blanket claim of complete framework-independent architecture compliance.

For explanations and source paths, see the published implementation guide.
