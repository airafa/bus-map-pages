Open DS Component API and Foundations Update ​

1. Scope ​

Compare the existing Bus Map design system and its previous Open DS baseline with the latest supplied Open DS version. Identify and fill verified gaps in the components, foundations, documentation and validation used by Bus Map.

Delivered in PR #4.

  • Previous reference: 3c8ff13.
  • Updated reference: Open DS 0.2.1 at 30d187b.
  • Include the applicable OD-234, OD-235, OD-239, OD-240 and OD-242 updates.
  • Preserve the CSS Modules adaptation, Floating UI controls and Lego dialog integration.
  • Do not add unused upstream catalog components, replace the UI framework or introduce unnecessary application dependencies.

2. Component token APIs ​

  • Synchronize the updated Dense data semantic and component tokens, retaining aliases.
  • Include all 1,299 upstream token keys rather than the previous 195-key subset.
  • Wire buttons, selects, menus, dialogs, panels and tables to their corresponding component token APIs.
  • Apply the scheme's typography, weights, control dimensions, borders and spacing through those APIs.
  • Keep shared overlay tokens for portaled surfaces where appropriate.
  • Preserve product overrides separately from generated upstream tokens.

3. Spacing and dialog presentation ​

  • Generate and document the component spacing map.
  • Use named layout roles between groups and named component steps inside components.
  • Keep Dense data spacing on its 4px grid, with steps up to 48px and the fixed 2px optical hairline.
  • Do not treat runtime table geometry, viewport dimensions or icon sizes as spacing.
  • Use the dialog container inset for header and content padding: 16px in Dense data.
  • Use the heading role for dialog titles and the body role for descriptions.
  • Preserve dragging, modal focus containment, focus restoration and nested select portals.

4. Theme states and responsiveness ​

  • Give menu items body-sized labels and visible dedicated hover feedback.
  • Keep select-option hover distinct from the selected fill in every product theme.
  • Require input and secondary-action control borders to meet the Open DS strong-border contrast threshold of 3:1.
  • Preserve quiet decorative panel and table borders.
  • Target Floating UI triggers, not obsolete native-select selectors, in responsive header and documentation styles.
  • Preserve all six product themes, monochrome-first ordering, the system-matched default and theme branding.
  • Preserve 36px table rows, table/Gantt selection backgrounds and 2px outlines, virtualized rows, route identities and production editor restrictions.

5. Documentation and decision reference ​

  • Record verified gaps and their implemented resolutions in the design-system documentation.
  • Add the updated Open DS version and component spacing map to the interactive showcase.
  • Show each applied decision's answer, reason and preceding dependencies.
  • Show the downstream answers, usage rules and component variants each decision determines.
  • Generate decision consequences using the upstream reference engine rather than maintaining a separate interpretation.
  • Keep components before the theme gallery and preserve documentation scrolling.

6. Validation and delivery ​

  • Run the matching local Open DS MCP and require its version to match the synchronized source.
  • Preserve local reference-folder modifications; use a complete separate reference checkout when runtime or builder files are missing.
  • Verify 30 applied decisions, including reasons, dependencies and consequences.
  • Read the button, input, select, table, dialog, dropdown-menu, context-menu and card guides.
  • Verify generated component aliases and values in light and dark modes, all spacing steps, scale landings and consumed per-theme token chains.
  • Check all six product palettes against live contrast guidance and run check_ui on affected UI sources.
  • Run existing design-system regression tests, strict package TypeScript checking and a production Yarn build.
  • Validate dropdown hover/selection, menu hover, nested dialog dropdown dismissal and Escape ordering in the browser across all six themes.
  • Validate narrow-screen headers, documentation scrolling, row outlines, virtualization and dialog typography/padding.
  • Commit and push the update through a pull request against main; merge when requested.
  • Keep GitHub Pages publication separate unless explicitly requested.
