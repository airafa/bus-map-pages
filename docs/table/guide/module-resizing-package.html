Module resizing ​

@busmap/module-resizing is a plug-and-play React component for a two-pane, responsive Grid split. Its only export is ResizableSplit. The component owns the Grid tracks, the 12px divider, pointer and keyboard interaction, min/max clamping, and its stylesheet. It does not depend on the Bus Map layout editor, Baseplate, Redux, a storage backend, or a drag-and-drop library. React 19.3.1 is its peer dependency. No Web Components are introduced.

Usage ​

jsx
import { ResizableSplit } from "@busmap/module-resizing";

<ResizableSplit
  leftContent={<Schedule />}
  rightContent={<RouteMap />}
  initialSplit={savedSplit}
  min={20}
  max={80}
  onSplitChange={split => saveSplit(split)}
  separatorLabel="Resize dashboard panels"
/>
PropTypeNotes
leftContent, rightContentReactNodeThe two panes. Below 840px they stack top and bottom.
min, maxnumberRequired. Percent limits for the first pane; must satisfy 0 < min <= max < 100, otherwise the component throws.
initialSplitnumberOptional, default 50. Clamped to the limits; a non-finite value falls back to 50. A later change (for example, a preference that finished loading) replaces the current split.
onSplitChange(split: number) => voidOptional. Called once per completed drag or key press, never during pointer movement.
separatorLabelstringAccessible name for the divider. Default "Resize panels".
className, styleApplied to the Grid root.

The component keeps the committed split in local state, so it works without any host store. Persistence is the host's choice: pass the saved value as initialSplit and store it from onSplitChange. Changing limits clamps the current split without calling onSplitChange; relaxing them does not restore an earlier out-of-range value. Fractional percentages are preserved in both pane geometry and the separator's accessible current value.

Mount ResizableSplit only where resizing is wanted. It renders a Grid root with flex: 1 1 0% and zero minimum sizes, so it fills a flex parent. A constrained parent height is needed for meaningful resizing in the stacked mobile layout.

Styles ​

The package entry imports its own stylesheet. Consumers do not import CSS; a bundler that supports CSS imports from dependencies (such as Vite) includes it automatically. The stylesheet uses locally scoped CSS Modules classes and optional design tokens: --size-control-default, --border-width-focus, --color-border-strong, and --color-border-focus. Fallbacks allow use without the Bus Map design system. The host must provide a visible, contrast-appropriate focus color.

Source workspace ​

The supported consumer is the Bus Map source workspace. Its package-manager link resolves @busmap/module-resizing to the typed source entry; the host bundler compiles the component and its CSS Module. No separate package build or dist directory is required. From the workspace root, using installed dependencies:

sh
yarn dev
yarn build
yarn workspace @busmap/module-resizing lint
yarn workspace @busmap/module-resizing test

For rendered interaction coverage, start Vite from the workspace root:

sh
yarn vite --host 127.0.0.1 --port 5173 --strictPort

Open a local Chromium page with remote debugging enabled on port 9334, then run from the workspace root:

sh
yarn workspace @busmap/module-resizing test:browser

The test exercises the public package import and reports failures from the rendered split fixture. BROWSER_CDP_URL overrides the loopback CDP endpoint; MODULE_RESIZING_FIXTURE_URL overrides the fixture URL.

The source-workspace test requires the package dist directory to be absent; it checks the app's development import, strict consumer typing, production compilation and scoped stylesheet. The component still requires a single compatible React instance. Source consumption alone does not establish offline installation or runtime readiness; those require the host's approved dependency artifacts and map resources.

Bus Map integration ​

Bus Map drives resizing from its layout JSON and gates it in the recursive layout renderer:

json
{
  "uuid": "bus-dashboard",
  "name": "layout",
  "layoutElementType": "LAYOUT",
  "style": { "display": "flex", "flex": 1, "minHeight": 0 },
  "resizable": true,
  "minSplit": 20,
  "maxSplit": 80,
  "items": [
    { "uuid": "schedule-pane", "name": "schedule", "layoutElementType": "LAYOUT" },
    { "uuid": "route-map-pane", "name": "route-map", "layoutElementType": "LAYOUT" }
  ]
}

An optional initialSplit sets the default percentage (otherwise 50). In app/src/components/Layout/Layout.jsx, a layout item renders ResizableSplit inside its ordinary Panel only when resizable === true and it has exactly two children (layout items plus assigned modules). Every other panel renders its content directly, with no resizing component in the tree. The saved split is stored per layout UUID as { "splitPercent": number } through the separate @busmap/user-preference-datasource package; the editor's split input reads and writes the same key.

Behavior and limitations ​

  • Below 840px, rows replace columns; the same ratio applies to both. The divider remains visible. Horizontal RTL movement and arrow keys are inverted; vertical movement is not.
  • The divider uses pointer capture and a 44px coarse-pointer hit area around the 12px track. At rest, React owns the committed geometry.
  • At most one preview frame is pending; geometry and direction are measured on pointerdown. On release the final value is committed; cancellation or lost capture commits the last previewed value. Unmount, breakpoint, limit, or committed-value changes cancel an obsolete drag without committing it.
  • onSplitChange is the integration boundary. The component does not handle persistence errors, remote APIs, or cross-tab synchronization.
  • Grid layout and child painting still cost time; 60fps is not guaranteed. The expanded touch target takes priority over nearby content in its narrow band. Test on real touch hardware.
  • Only two panes are supported. Additional dividers, pixel minimums, snapping, undo, or separate mobile ratios need separate work.
