Integrate with the application starter kit ​

External-consumer example

This guide describes a separately consuming starter-kit application. It is not the Bus Map source-workspace setup; use the source-workspace quick start for this repository.

This guide uses the structure of lego-application-starterkit-dnd-main: Yarn 1 workspaces, an app, and independently packaged feature modules. The table package belongs in the consumer's view layer. It does not belong in the application's state, transport, or domain layers.

For the current pane-resizing package, see the module resizing package guide. Module-pane resizing is separate from table-column resizing.

For application-owned row behavior, follow Row selection and context-menu integration. It walks through shared selection state, row gestures, an independent menu host, and action routing in another starterkit application.

1. Resolve the React peer dependency first ​

Prefer the latest stable React release for new integrations and upgrades, with matching react-dom and compatible React type packages across all workspaces. The current Bus Map application uses React and React DOM 19.3.1.

This release of @busmap/table declares react@19.3.1 as an exact peer. Newer stable React versions are the recommended upgrade target, but they are not automatically supported by this exact declaration. Validate the upgrade and use a table release whose peer dependency supports the chosen version.

Before installing this release, plan and test a coordinated React and React type upgrade across the relevant workspaces, or use a package release whose peer dependency supports the application's React version. Do not use --legacy-peer-deps or force an incompatible resolution; duplicate or mismatched React types/runtime can break hooks and component rendering.

The package is also not currently available from the public npm registry. Point the @busmap scope at the registry that hosts it in the repository-root .npmrc, then, after resolving React compatibility, add it to the module that renders the table:

sh
yarn workspace @starterkit/module-entity-list add @busmap/table

The starter kit expects workspace dependency changes to be run from its root. If the package is not yet published to a configured registry, build and pack the table repository, then add the resulting local tarball to the workspace.

2. Keep the application boundary clear ​

An appropriate placement for a table in this starter-kit structure is:

text
modules/
  module-entity-list/
    src/
      store/                 # application-owned state and selectors
      components/
        RouteTable.tsx       # app-owned mapping and composition
packages/
  table/                     # independently reusable renderer and behavior
app/
  src/index.render.tsx       # application entry imports package CSS once

The consuming module reads application state, applies domain-specific rules, and passes a typed row collection and callbacks to its view. In this starter kit, a module's own Redux slice/selectors are one existing place for that work. In an architecture using shared DataSources, the module may instead receive the projection from its DataSource/module boundary. In either case, @busmap/table receives already-prepared rows and column definitions. It must not import the starter kit, its Redux store, DataSources, transports, route models, or business rules.

The package handles table rendering, its sizing and sorting features, and optional virtualization. The consuming module decides which columns to show, which rows to provide, how row selection works, and how the table fits its module lifecycle.

For a schedule view that renders a @lego/graphs Gantt per row, follow the Gantt-column integration guide. Keep the graph package, custom-element registration, and schedule-to-graph data mapping in the consuming application/module; none of those are dependencies of @busmap/table.

3. Import styles at the app entry ​

In the starter kit's React render entry, add:

tsx
import "@busmap/table/style.css";

Keep application-specific theme and layout CSS in the consuming app or module. The package does not provide a theme provider or require the starter kit's design-system package.

4. Define typed columns in the consuming module ​

The following is a self-contained React view example for a module component. routes is an input prepared by the application; the package does not fetch or derive it.

tsx
import {
  createColumnHelper,
  ResizableTable,
  TableSortControls,
  resizableTableFeatures,
  useResizableTable,
} from "@busmap/table";

export type RouteRow = {
  id: string;
  route: string;
  destination: string;
  activeVehicles: number;
};

const column = createColumnHelper<typeof resizableTableFeatures, RouteRow>();
const columns = column.columns([
  column.accessor("route", { header: "Route", size: 120, minSize: 88 }),
  column.accessor("destination", { header: "Destination", size: 220, minSize: 140 }),
  column.accessor("activeVehicles", { header: "Active vehicles", size: 128, minSize: 96 }),
]);

export function RouteTable({
  routes,
  virtualize = false,
}: {
  routes: RouteRow[];
  virtualize?: boolean;
}) {
  const table = useResizableTable({
    columns,
    data: routes,
    getRowId: route => route.id,
  });

  return (
    <section className="route-table">
      <TableSortControls table={table} label="Sort routes by" />
      <ResizableTable
        table={table}
        label="Bus routes"
        virtualize={virtualize}
        className="route-table__scroll"
        style={{
          "--table-row-height": "40px",
          "--table-header-background": "var(--surface-raised, #fff)",
        }}
      />
    </section>
  );
}

In the actual feature module, obtain the routes input from the module's selector or other application-owned boundary. Keep route sorting policy, permission checks, selection state, and any API calls outside this generic component. getRowProps can pass row attributes or event handlers when the consumer needs them; see the API reference.

5. Compose and validate ​

TableSortControls is optional. ResizableTable renders the columns and resizing separators without it. Set virtualize to true only when the view needs row virtualization; it is false by default.

Build and type-check the consuming workspace using its existing root scripts. Test the module's selector-to-view mapping separately from the package, and test the table interactions at the component boundary. See Accessibility and testing.

Compatibility exports ​

The original Bus Map application retained re-exports of table components and utilities from its own @busmap/design-system package to ease migration. Those are application compatibility paths; they are not a dependency or export of this standalone package. For a new consumer, import from @busmap/table. An existing Bus Map consumer can migrate imports incrementally, then remove its old compatibility re-exports when no longer needed. Do not add a dependency on the Bus Map design system just to use this table package.
